# 长期规划

## 已确认目标

一个 farm 主仓库统一开发农场逻辑；面向真寻、普通 NoneBot 和
AstrBot 生成不同插件；三个发布仓库只承载各自的安装内容。
用户不需要下载其他框架的接入代码。

保留旧项目功能作为需求调查基础，不默认旧实现正确，也不默认旧
README 中所有功能都要无条件保留。先修数据一致性，再增加玩法。

## 建议的首个版本范围

保留开通农场、查看、种子商店、购买、播种、收获、铲除、出售、
锁定、土地升级、签到、偷菜、改名。逐项核对旧指令与返回行为。
真寻金币兑换为真寻专有可选能力；其他框架不凭空生成外部金币。
点券、远程签到与星级规则在决策确认后进入规格。

首版不做交易行、钓鱼、跨实例在线联机、账号自动绑定、Web 后台、
通用插件引擎、复杂事件总线和微服务。后续依据需求增加。

## 里程碑和退出条件

| 阶段 | 工作 | 完成标准 |
|---|---|---|
| M0 初始化 | 代码保全、审查、设计和忽略规则 | 哈希可验证；实现与计划状态清楚 |
| M1 规格收敛 | 确定身份、共享范围、经济与迁移策略 | 决策表关键项已确认，行为示例可验收 |
| M2 核心与存储 | 注册、货币、库存、迁移及事务 | 无框架依赖；失败回滚、重试幂等、并发余额测试通过 |
| M3 种植闭环 | 购买→播种→收获→出售、土地升级 | 边界、星级、锁定、经验计算及时间测试通过 |
| M4 真寻接入 | 保留既有用户入口，迁移旧数据 | 真实宿主的安装、启停、文本/图片与恢复演练通过 |
| M5 其他接入 | 普通 NoneBot、AstrBot | 每个宿主独立安装；无其他框架依赖；功能矩阵通过 |
| M6 发布链路 | 分包、来源清单、发布仓库同步 | ZIP/wheel 安装测试、凭据与体积检查、可重试发布通过 |
| M7 稳定运营 | 性能、备份、资源供应与升级 | 有容量指标、兼容矩阵和版本回滚演练 |
| M8 可选联机 | 独立服务、账号映射、共享状态 | 另立需求，不直接共用多个进程的 SQLite 文件 |

阶段顺序表达依赖，不作未经验证的工期承诺。M4/M5 先打通一个最小
指令与完整交易闭环，再扩展全部指令；不要先写完所有框架外壳。

## 质量门槛

- 新玩法先给数值和边界例子；保留用户接受的契约。
- 每次修改聚焦一个可验收用例，避免同时换数据库、框架和玩法。
- 测试以交易不变量、并发、迁移和真实安装为主，不只检查函数返回。
- 核心测试不能依赖机器人、外网或图片渲染器。
- 每次发布追溯到主仓库提交、目标、资源版本、schema 和依赖清单。
- 所有目标达到对应门槛才能称为“支持”；未实现目标保持禁用。
